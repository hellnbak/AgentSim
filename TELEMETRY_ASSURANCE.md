# Telemetry assurance and detection packs

AgentSim 1.3 separates two questions that are often conflated during detection
testing:

1. Is the evidence safe and trustworthy enough to correlate?
2. Given that evidence, which reviewed detection rules match?

The telemetry doctor answers the first question. Detection-pack sweeps answer
the second without consulting scenario ground truth. Neither feature queries a
vendor, starts a process, deploys a rule, or retains raw prompt/tool content.

## Telemetry doctor

```bash
agentsim telemetry doctor export.jsonl --collector agent_runtime
agentsim telemetry doctor export.jsonl \
  --collector otel_genai \
  --output assurance.json \
  --fail-on degraded
```

Checks include:

- source timestamp presence and validity;
- proof that the bounded redaction projection ran;
- stable, unique source event/span identity;
- `trace_id`, `session_id`, and `agent_id` coverage;
- identities generated by normalization because the runtime omitted them;
- resolution of `parent_event_id` and `caused_by_event_ids`;
- cross-trace causal links and causal timestamp inversions; and
- content-bearing field names or `content_recorded: true` crossing the safe
  telemetry boundary.

| Status | Interpretation |
| --- | --- |
| `healthy` | No assurance finding was observed in the supplied evidence. |
| `degraded` | Evidence can still be inspected, but at least one correlation-quality issue requires review. |
| `unusable` | A critical boundary failed or cumulative quality loss makes detection conclusions unsafe. |

The default command exits `1` only for `unusable`. `--fail-on degraded` also
fails on degraded evidence. `--fail-on never` always returns `0` after a report
is emitted. The schema is
[`schemas/telemetry-assurance-report.schema.json`](schemas/telemetry-assurance-report.schema.json).

An assurance score is a triage aid, not a certification. A healthy report does
not prove telemetry completeness outside the supplied window, sensor accuracy,
or that a detection should alert.

## Detection packs

The packaged default is `agentsim.agent-security-core` version `1.0.0`. It
contains ten content-safe investigative rules covering:

- untrusted or tainted high-risk tool requests;
- allowed high-risk requests and defended policy denials;
- missing policy or principal attribution;
- untrusted memory writes;
- high-risk MCP tool requests; and
- invalid authorization audience or per-client consent.

The built-in reference-agent corpus supplies malicious and benign MCP
authorization checkpoints for both audience and consent, so all ten default
rules have the declared source fields. A real export can still produce a
visibility gap when its runtime omits those checkpoints.

```bash
agentsim detection sweep agent-events.jsonl --collector agent_runtime
agentsim detection sweep agent-events.jsonl \
  --collector mcp_audit \
  --pack organization-agent-pack.json \
  --output sweep.json \
  --fail-on-visibility-gap
```

Each rule uses the existing non-executable detection AST and declares
`required_fields` plus acceptable `expected_sources`. The loader verifies that
declarations cover every predicate, grouping, threshold, process-correlation,
and causal-link field used by the AST. Pack size, identifiers, duplicate rules,
and unknown top-level fields are bounded or rejected.

| Sweep status | Interpretation |
| --- | --- |
| `detected` | The rule matched normalized bounded evidence. |
| `not_detected` | All declared evidence was available and the rule did not match. |
| `visibility_gap` | The rule did not match and at least one declared source or field was absent. |

Sweep reports always include `ground_truth_used: false`. The loader rejects
`expected_detection`, `expected_detected`, `ground_truth`, and
`scenario_variant`; these labels belong only in an isolated evaluation join.
Schemas are
[`schemas/detection-pack.schema.json`](schemas/detection-pack.schema.json) and
[`schemas/detection-sweep-report.schema.json`](schemas/detection-sweep-report.schema.json).

## Python API

```python
from agentsim.api import collect_telemetry, detection_pack_sweep, telemetry_assurance

events = collect_telemetry("agent-events.jsonl", collector="agent_runtime")
quality = telemetry_assurance(events)
sweep = detection_pack_sweep(events)
```

Pass `pack_path="reviewed-pack.json"` to `detection_pack_sweep` for custom
content. The returned values are JSON-serializable schema objects.

## Recommended workflow

1. Export an exact, bounded test window.
2. Normalize it with the correct collector profile.
3. Run the telemetry doctor and resolve critical/high findings.
4. Run a detection-pack sweep for investigative coverage.
5. Run malicious/benign regression separately when ground truth exists.
6. Tune and validate the vendor-native candidate outside AgentSim before any
   production deployment.

The Web workspace exposes the same checks against the synthetic reference-agent
corpus. It is a human debugging aid and cannot upload production telemetry or
contact a SIEM.
